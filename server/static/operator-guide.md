# PianoVal 运营训练与跟弹测试使用说明

## 先理解判断依据

当前已有 O&V 预训练钢琴模型，无需从零训练即可测试。

- **参考曲谱 / 左右手 MIDI**：定义学生此刻应该弹什么。
- **学生本次录音**：经模型识别，得到实际听到的 MIDI 音高和起音。
- **跟弹等待**：比较当前目标与实际识别音。音高集合完全匹配才前进；错音、多音、缺音时停在原处，纠正后再试。静音和时间流逝不会推进。
- **训练答案**：必须记录本次演奏实际弹出的音。学生把 C 弹成 D，答案应标 D，不能拿标准曲谱的 C 代替。

左手模式使用左手 MIDI，右手使用右手 MIDI，双手合并同时发生的目标音。
麦克风不能确定演奏者实际使用了哪只手；模式约束的是目标声部。
当前严格策略下，左手模式若同时弹了额外右手音，也会等待。
当前模型识别起音及 MIDI 音高，不测量音分偏差，不识别松键时刻或踏板状态。

## 一、用虚拟钢琴快速验证

打开 <http://localhost:8765/#piano>，也可点击左侧“虚拟钢琴”。

**不用会弹琴也可以一键测试：**

1. 先选曲目与版本、左手 / 右手 / 双手、小节范围、BPM 和识别模型；建议先测前 2 小节，再测默认前 8 小节。已有 14 首、17 个版本，支持“随机曲目”或“随机曲目并测试”。
2. 点击“完全正确弹”，系统自动连接模型，按参考 MIDI 用真实钢琴采样演奏，末尾自动结束并生成结果。
3. 点击“随机错误弹”，按所选错误比例，在部分音符组中换错音、多弹音或漏弹和弦音。每轮随机生成，完整结果保留随机种子与实际发声记录。
4. 等待自动测试完成，查看“自动测试结果”：正确输入组、插入错音组、正确组识别误拦、错音组识别误放行、错音检出和音符 F1；表格逐组列出谱面、自动弹奏、模型听音与判定。
5. 自动测试会保存报告和可回听的模拟录音，下方“测试历史与排错日志”可再次查询。点击“下载完整结果”也可另存本轮报告。提前点“停止自动测试”只生成已经弹过部分的结果，页面或音频连接异常会标记为中断。

自动弹奏会按谱弹完整段，即使模型使跟弹卡住，也继续收集后续音符。**实际跟弹进度仍由模型结果决定，不会强制放行或重置卡点。**
下方的逐组对照独立判断每次弹奏的识别结果，用于定位误报 / 漏报；它不表示跟弹游标已经通过所有这些组。
“完全正确弹”表示生成的输入符合曲谱，不保证当前模型全部识别正确。结果是模拟输入准确率，不能直接作为学生实弹准确率。
自动测试期间请保持页面在前台；手动琴键和辅助弹奏按钮暂时锁定，防止混入其他声音。

**需要手动测试时：**

1. 选择简易版 / 普通版、左手 / 右手 / 双手、小节范围和模型。
2. 保留“听音辅助（跟弹等待）”，点击“启动模拟测试”。等到键盘上方显示“可以弹了”，再按琴键；准备中暂不弹。进入“虚拟钢琴”默认使用跟弹引导，固定节拍模式可点击“开启按键引导”切回。
3. 不用懂音名：点击蓝色箭头下写着“点这里”的键，按住约半秒再松开，等待模型返回。和弦会编号标出全部目标键，Pad 可多指同时按；用鼠标时可点“帮我一起弹这组”。点击“帮我弹这一键”也会生成真实采样音频供模型识别。只有模型识别通过后，蓝色目标才切换；上方音名标签仅定位琴键。
4. 可以点击“弹当前正确目标”“弹一个错音”快速制造测试场景。这些按钮只发声，不直接推进曲谱。
5. 和弦测试：开启“组和弦”，点击琴键选音，再点“一起弹选中和弦”。也可在电脑键盘同时按多个键。
6. 调整力度，或勾选延音踏板测试残响。模拟踏板影响生成音频，模型本身不输出踏板识别结果。
7. 点击“结束并对照”，查看实际触发音与模型识别的匹配、误报、漏音，下载本次测试报告。

默认电脑键盘从 C3 开始：Z、S、X、D、C、V、G、B、H、N、J、M 等依次对应半音；Q、2、W、3、E 等从高一个八度开始。可切换键盘起始八度。输入框获得焦点时不触发电脑琴键。

音频路径是：真实钢琴采样发声 → AudioWorklet 连续 PCM → WebSocket → 服务端真实模型 → 跟弹判定。
按键 MIDI 另作已知输入记录，**不传给模型作识别答案，不用于绕过模型推进**。
琴键旁会分别显示“你按下的键”“模型听到的音”。“实际触发”表示按键已经发声，不代表模型判定通过。
如果按对了却卡住，先查看这里：正在识别时等待几秒；如果提示“你已按对，模型识别出现偏差”，
说明模拟输入已知正确，但模型在该次起音附近多报或漏报。例如仅按 E4，模型可能返回 E4 + E5，严格跟弹就会停住。
这是当前模型在钢琴采样上已复现的误报，不能要求用户一直重复点击来当成解决办法；需保留录音和识别明细，复核并评测候选模型。
这个诊断只解释结果，不把已知按键当作识别结果放行。真实麦克风弹奏没有按键真值，仍需教师复核。
结束后保存的模拟录音带有模拟标记，可复核、试跑微调，但不能通过该数据启用正式候选模型。

### 一键测试的准确率怎么看

点击“完全正确弹”或“随机错误弹”，页面在弹奏过程中实时显示**逐组判断正确率**：
`（正确弹奏放行组 + 错音正确拦截组）÷ 已评测组`。
模型还没分析完整起音窗口的组显示“等待模型”，不计入分母，也不提前计为误拦。
全段演奏和音频识别都结束后，显示“最终逐组判断正确率”；手动停止或连接失败只显示已评测部分。

“完全正确弹”的输入全部符合参考 MIDI；这时出现误拦，表示模型输出与已知正确输入不同，不能记成学生弹错。
例如 25 组正确输入中 10 组被误拦，判断正确率就是 `(25 − 10) ÷ 25 = 60%`，误拦率为 `40%`。
表格会列出实际按键、模型听到的音，以及具体多识别 / 漏识别的音。

下方折叠项中的**音符识别 F1**按单个音符计算，是精确率与召回率的调和平均，与逐组判断正确率不同。
例如匹配 29 音、误报 10 音、漏音 0，F1 为 85.3%；它不能解释成“85.3% 的跟弹判断正确”。
实际跟弹进度另外展示：第 2 组卡住时，自动测试继续覆盖余下音符，进度可能是 1/25，但评测仍覆盖 25/25 组。
下载完整结果可查看 `analysis.accuracy`、已评测 / 等待组数、原始事件和实际跟弹轨迹。

建议先验收这些场景：

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 左手单音 | 弹当前左手目标 | 模型正确识别后前进 |
| 右手错音 | 弹错音，再弹正确目标 | 错音等待，纠正后前进 |
| 双手和弦缺音 | 只弹和弦中的一个音 | 等待并显示缺少的音 |
| 双手完整和弦 | 同时弹完整目标 | 模型正确识别后前进 |
| 多弹一个音 | 和弦增加一个错音 | 等待并显示额外音 |
| 暂停 / 慢弹 | 不弹、等待，再继续 | 不因时间过去跳步 |
| 力度与延音 | 改变力度、使用踏板 | 记录误报漏音，观察残响影响 |

当前 `piano-stream-v2` 模型配置需要 **288ms 右侧上下文**，还需计算、起音判定窗口、批处理和网络时间。
自动测试显示从真实发声到完整判定结果返回的 P50 / P95 / 最慢延迟，以及模型计算和网络往返，不能把 288ms 当成总延迟。
页面默认展示自动测试逐组对照，下方视图可切换到“实际跟弹轨迹（错音停留）”；两者分别展示，不用已知按键强行推进跟弹。
当前校准配置在本地采样留出测试中判断正确率为 97.4%，真实学生录音与生产网络仍需独立验收。
模拟器使用录制钢琴采样，不包含真实房间、Pad 麦克风、噪声和串音；模拟分数不能代表真实学生准确率。

## 二、测试学生真实跟弹

打开“曲谱实测”，声音来源选“麦克风实弹”，选择模式、声部和片段。

1. 勾选“完整结束后保存跟弹录音”。点击“开始听琴”，就绪后开始弹奏。
2. 跟弹等待不需要用 BPM 或起点偏移对齐演奏。当前和弦的起音判定窗口为 120ms；超过窗口的琶音可能被拆成缺音，应单独记录验证。
3. 卡住时先不要假定是学生弹错。记录当前目标、模型最近识别的音，纠正或重弹观察。
4. 完整结束后，点击“复核这次跟弹录音”，回听实际声音。
5. 在“跟弹判定明细”由老师复核：实际弹对但等待，标“实际弹对，应通过”；实际有错却前进，标“实际有错，应等待”。两类分别是误拦和误放行。
6. 正常结束后，报告与老师本次复核自动写入服务端，下方“测试历史与排错日志”可下载完整日志、回听录音；刷新页面后记录仍在。

不要只挑卡住片段：通过的片段也需抽查，否则无法发现误放行。等待次数不等于模型错误率。
模型完全漏掉一个起音时可能没有判定行，应回听完整录音，在录音标注中补上。
连接意外中断时也保存已收到的部分录音（至少 0.25 秒），标为未完整完成。未勾选保存录音只能查看日志；未传到服务器的音频无法恢复。强制终止服务或断电不能保证最后一段完整。

每次测试不会自动学习或改动模型。实弹报告保留为“待复核”，不能把通过组数除以总组数当作识别准确率。老师核验实际音符后，运营再分配训练 / 独立验证素材，显式启动微调。
当前可下载历史报告与回听录音；尚未绑定教师 / 学生账号，也未提供刷新后重载历史判定表继续编辑的界面。原始音符概率、逐窗推理耗时、配置和异常状态可在完整日志中排查。
“老师复核判对率”只计算已经人工标记的判定，并显示复核数量，不代表未复核段落或整段声音的准确率。

“固定节拍对照”是另一种可选模式：按 BPM、片段和录音起点偏移核对录音与标准演奏时间。它不等同于自由速度跟弹等待，也不能独自证明识别准确率。

## 三、准备与标注训练素材

运营组织真实教室、真实设备的录音，老师核验实际音符。

1. “录音与标注”上传 WAV、MP3、M4A、FLAC 等。单条 0.25～600 秒，单文件不超过 50MB。
2. 文件名记录曲目、设备、原始录音和片段。保留低音、和弦、弱音、连奏等需要改善的真实场景。
3. 点击“识别这段录音”得到草稿；老师回听整段，补漏音、删误报、纠正音高与起音。不要把模型预测不经复核直接作为答案。
4. 有同次演奏的同步 MIDI，可导入 .mid。整段存在统一延迟时用 MIDI 偏移校正：MIDI 在 0 秒、录音在 1 秒起音，填 +1。偏移不能修复速度变化或不同演奏。
5. 没有同步 MIDI，就人工修订音符。谱子照片、PDF、MusicXML、标准演奏 MIDI 只是参考，不能直接替代本次声音的标注。
6. 整段核对后勾选“已核对整段音频”，保存标注。未核验录音不会进入训练。

标注每行格式为“起音秒数, MIDI 音高, 力度”：

```text
0.600, 60, 80
1.200, 64, 80
1.200, 67, 80
```

上例为 0.6 秒的 C4，1.2 秒同时弹出的 E4、G4。C4=60；以 MIDI 数字为准。
时间从录音开头算，不能超出录音长度。当前微调不训练力度，没有可靠力度数据时可填 80。

## 四、划分训练集与验证集

- 训练集用于学习，验证集用于比较基础模型与候选模型，不能重复。
- 同一曲目、同一原始录音切出的片段 / 重录使用同一“曲目 / 采集分组”，放在同一边。
- 系统阻止同分组和完全相同音频跨两边；运营仍需识别改名、转码、裁切后的重复素材。
- 流程最低需要 1 条已核验训练录音和 1 条独立验证录音。这只是运行门槛，不是准确率验收所需样本量。
- 真实训练前点击“将演示数据移出训练集”。演示 / 模拟与真实录音不能混合训练。
- 应保留另外的独立测试素材，覆盖左手、右手、双手、不同琴和设备；不要反复调同一个小验证集。

## 五、启动微调并验收

1. 进入“模型训练”，检查数据用途、分组和核验状态。
2. 首次可用 20～50 步、学习率 0.0001、随机种子 42，点击“开始微调与验证”。这些是试跑设置，不保证提升。
3. 系统先测基础模型，再训练最后一个起音识别阶段，最后用相同独立验证录音测候选模型。
4. 每轮从基础预训练权重开始；不会自动接着上一次候选继续训练。可离开页面，服务运行时后台继续；停止服务会中断任务。
5. 保存任务编号、素材分组、验证结果及跟弹报告。

| 指标 | 含义 |
| --- | --- |
| TP / 正确匹配 | 相同 MIDI 音高，起音相差不超过 50ms，一对一匹配 |
| FP / 误报 | 听出了实际上没弹的起音，包括多报、重复报 |
| FN / 漏音 | 实际弹出的音没有匹配到 |
| 精确率 | 预测中正确的比例，关注误报 |
| 召回率 | 实际音符被识别出的比例，关注漏音 |
| F1 | 综合精确率和召回率 |
| 训练损失 | 学习过程数值，下降不等于独立验证或跟弹体验提高 |

只有真实数据的独立验证 **F1 提高且精确率未下降**，才允许启用候选；演示 / 模拟数据训练不开放正式启用。
先在曲谱实测选择候选模型进行回放和现场跟弹，检查误拦、误放行，再决定启用。
切换前停止活动录音会话；新会话使用新模型。出问题可“使用基础模型”回退。
如果没有提高，先检查标注、录音偏移、数据重复和场景代表性，不要只增加步数。

## 六、设备与部署

本机从 localhost 测试；Pad 需要能访问服务的地址及有效 HTTPS / WSS，不能使用 Pad 自己的 localhost。
本页当前是本地测试台，未修改或部署原练习网站；原站需要接入同一个服务，才能使用该模型。
音频与权重保存在本机服务目录；运营应由技术人员协助备份。
录音时避免播放外放伴奏或旁人讲话，实际噪声场景另作独立测试；麦克风后台、锁屏与 Pad 多点触控需真机验收。
